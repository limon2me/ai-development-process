# Общий процесс разработки с ИИ

Пакет задаёт согласованный порядок работы для любых проектов: изучение → ТЗ → архитектура и блоки → тесты → реализация → независимое ревью → приёмка блока → приёмка задачи в использовании.

Общие правила и навык хранятся в этом отдельном Git-репозитории. Первое подключение на каждом компьютере и в каждой среде пользователь выполняет самостоятельно. Подключение не изменяет проекты.

| [Передача работы](skills/product-development/references/handoffs.md)         | Независимые сессии, состояния файлов, принятые тесты и продолжение.                                         |

Навык оформлен по [Agent Skills](https://agentskills.io/specification). Его папка содержит всё необходимое для процесса; ссылки навыка ведут только к файлам внутри неё. Особые инструменты, язык программирования, Linear не являются условием работы. Без встроенных помощников используются отдельные чаты; без Linear локально сохраняется описание задачи, подготовленное для Linear.

## Codex: общие правила

Откройте глобальный `~/.codex/AGENTS.md` и добавьте в него полный текст [RULES.md](RULES.md), сохранив остальные свои инструкции. Если задан другой `CODEX_HOME`, используйте его каталог. Если уже есть непустой `AGENTS.override.md`, Codex читает его вместо глобального `AGENTS.md`: поместите блок процесса в реально используемый файл. Начните новую сессию после изменения. [Официальный порядок загрузки](https://learn.chatgpt.com/docs/agent-configuration/agents-md).

Не ограничивайтесь ссылкой на этот репозиторий в md-файле правил: текст обязательных правил должен быть в глобальных инструкциях. Так согласования остаются видимыми до загрузки навыка.

## Codex, Cursor и Claude Code: один локальный навык

Codex и Cursor используют пользовательский каталог `~/.agents/skills`; Claude Code — `~/.claude/skills`. Все три среды поддерживают формат [Agent Skills](https://agentskills.io/specification), а Claude Code также читает навык из символической ссылки. Поэтому на каждом компьютере можно подключить одну папку этого репозитория сразу в оба каталога. [Codex](https://learn.chatgpt.com/docs/build-skills), [Cursor](https://prod.cursor.com/docs/skills), [Claude Code](https://code.claude.com/docs/en/skills).

Сначала проверьте, нет ли уже `product-development` в каждом используемом каталоге навыков. Сохраните существующие версии и выясните их происхождение; не создавайте несколько копий с одинаковым именем. При свободных путях:

```sh
mkdir -p "$HOME/.agents/skills" "$HOME/.claude/skills"
ln -s "$PROCESS_REPO/skills/product-development" "$HOME/.agents/skills/product-development"
ln -s "$PROCESS_REPO/skills/product-development" "$HOME/.claude/skills/product-development"
```

Если предпочитаете копирование, перенесите **всю** папку `skills/product-development`, включая `references`, в каталоги тех сред, которыми пользуетесь: `~/.agents/skills/product-development` для Codex и Cursor, `~/.claude/skills/product-development` для Claude Code. Такие копии после обновления репозитория нужно обновлять отдельно. Для обнаружения навыка начните новую сессию; при необходимости перезапустите приложение. Имя навыка — `product-development`.

Эти пути относятся к локальному компьютеру. При работе в удалённой среде проверяется её собственное подключение; локальная установка не доказывает его наличие там. [Ограничения переноса навыков Cursor](https://prod.cursor.com/docs/skills), [расположение навыков Claude Code](https://code.claude.com/docs/en/skills#choose-where-skills-load).

## Cursor: общие правила

В настройках **Customize → Rules → User Rules** добавьте полный текст [RULES.md](RULES.md), сохранив остальные инструкции. Этот механизм применяется ко всем проектам в Agent (Chat). Он не применяется к Tab и Inline Edit; проверку процесса выполняйте в Agent. [Официальная документация](https://prod.cursor.com/docs/rules).

Начните новый чат и выполните [проверку подключения](connection-check.md).

## Claude Code: общие правила

Откройте `~/.claude/CLAUDE.md` и добавьте полный текст [RULES.md](RULES.md), сохранив остальные инструкции. Это пользовательские инструкции для всех проектов Claude Code на данном компьютере. Начните новую сессию и выполните [проверку подключения](connection-check.md). [Официальная документация](https://code.claude.com/docs/en/memory#choose-where-to-put-claude-md-files).

Путь `~/.claude/skills/product-development` подключает навык локально в Claude Code; он не устанавливает его в веб-сессии или другую удалённую среду. Для таких сред подключение проверяется отдельно.

## Codex: общие правила

Добавьте полный текст `RULES.md` в глобальный `~/.codex/AGENTS.md`, сохранив остальные инструкции. Если задан другой `CODEX_HOME` или непустой `AGENTS.override.md`, внесите правила в фактически используемый файл. Затем начните новую сессию и выполните проверку подключения.

## Среда без поддержки навыков

Добавьте текст `RULES.md` в её глобальные пользовательские инструкции. Передайте `SKILL.md` обычным документом или текстом, а относящиеся к текущему шагу файлы из `references` приложите по запросу ИИ. Все документы шагов можно приложить сразу, если среда не умеет открывать связанные файлы. Содержание и согласования остаются теми же.

Стартовая фраза для такой среды:

```text
Применяй приложенные RULES.md и product-development/SKILL.md
как мой процесс разработки. Описания шагов находятся в приложенных
references. Начни с исследования моего проекта и ближайшего
несогласованного шага; уже подтверждённые решения сохрани.
```

Если среда не имеет доступа к проекту, приложите требуемые проектные материалы и сообщите об этом ограничении. При отсутствии самостоятельных команд проверки ИИ готовит инструкции, пользователь запускает их и возвращает фактические результаты. ИИ не утверждает, что исследовал недоступные файлы или выполнил команды.

Если среда вообще не поддерживает глобальные инструкции, передавайте правила в начале каждого рабочего чата. Это ручное подключение; обязательность во всех новых чатах автоматически не обеспечена.

## Правила проекта и отдельные авторы

Существующие проектные инструкции остаются в проектах. Общий пакет задаёт порядок согласований, а проект — свои ограничения и проверки. При конфликте ИИ должен показать конкретное противоречие до реализации. У сред есть собственный приоритет инструкций, поэтому проверка фактического поведения обязательна; один глобальный файл не является техническим блокировщиком команд.

Один навык ведёт все шаги. Автор тестов, автор реализации и ревьюер — три разные сессии с ограниченными материалами по [порядку передачи](skills/product-development/references/handoffs.md). Без помощников пользователь открывает отдельные чаты. Смена названия роли в одном чате не обеспечивает независимость. Исходное состояние проекта для автора тестов сохраняется отдельно от новой реализации.

## Первый пример

Первый рабочий пример — [LIM-7 из coinlisting-bot](https://linear.app/limon2me/issue/LIM-7). До его продолжения пользователь уточняет и принимает [формат ТЗ](skills/product-development/references/specification.md). ТЗ готовится из существующих требований задачи, текущего состояния проекта и принятых решений. Дальнейшая работа проходит общий процесс. Проверка пакета и подключений не считается приёмкой изменений проекта.
