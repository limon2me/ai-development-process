# Проверка подключения на каждом компьютере

Эту проверку пользователь выполняет после первого подключения и после обновлений на каждом компьютере в каждой используемой среде. Нужны установленный навык и новые чаты. Загрузка документов вручную проверяет ручной режим.

## 1. Проверить запрос без вызова навыка

Начните новый чат в любом проекте. Передайте обычный запрос, не упоминая навык и не прикладывая его файлы:

```text
Как бы ты добавил экспорт списка в CSV? Дай краткий план. Ничего не меняй.
```

Ожидается обычный ответ по правилам среды и проекта, без запуска `product-development` и загрузки его обязательных правил. Схожие требования самого проекта допустимы: проверяйте источник правил и фактические обращения к файлам навыка, когда среда их показывает. В установленной копии Codex значение `policy.allow_implicit_invocation` в `agents/openai.yaml` должно быть `false`. В Claude Code в заголовке `SKILL.md` должно стоять `disable-model-invocation: true`.

## 2. Проверить явный вызов

Начните другой новый чат и явно вызовите установленный навык. Для Codex:

```text
Используй $product-development для учебной задачи «экспорт списка в CSV».
Прочитай обязательные правила и описания шагов. Назови их источники,
контрольные точки согласования, порядок работы авторов и условие завершения.
Ограничься объяснением процесса. Ничего не меняй.
```

В Claude Code используйте `/product-development` в начале сообщения. В ручном режиме приложите `SKILL.md` и документы из `references`, включая `rules.md`.

ИИ должен прочитать `references/rules.md` из папки навыка и связанные описания ТЗ, архитектуры, передачи работы и приёмки. Ответ должен назвать согласования, раздельных авторов тестов, реализации и ревью, а также приёмку пользователя. Проверьте фактические источники: одного названия навыка в ответе недостаточно.

## 3. Проверить границы задачи

В том же чате, без повторного вызова, напишите:

```text
Продолжим ту же учебную задачу. Какие сведения нужны для подготовки ТЗ?
Ничего не меняй.
```

Процесс остаётся применимым к этой задаче. Затем обозначьте другую задачу без вызова навыка:

```text
Теперь другая задача: как бы ты добавил переключение светлой и тёмной темы?
Дай краткий план. Ничего не меняй.
```

Правила `product-development` не должны переноситься на новую задачу автоматически. Для продолжения прежней задачи в новом самостоятельном чате явно вызовите навык снова и передайте сохранённое состояние; подтверждённые согласования должны сохраниться.
