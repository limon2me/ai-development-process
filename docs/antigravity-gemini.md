# Особенности работы навыка `product-development` в Antigravity и на моделях Gemini

Этот документ и плагин `plugins/product-development-agy/` содержат настройки и ограничения, компенсирующие слабые места младших и быстрых моделей Gemini (`Gemini 3.8 Flash`) и особенности среды Antigravity. Основной навык в `skills/product-development/` остаётся независимым от инструмента.

## 1. Слабые места младших моделей Gemini и как они перекрыты

По журналам реальных задач (`LIM-31`) при работе на быстрых моделях Gemini проявляются пять типичных сбоев:

| Проблема модели / среды | Как перекрывается в Antigravity |
| --- | --- |
| **Чтение длинных файлов не до конца** (обрыв на 100-й строке в `CLAUDE.md` и `handoffs.md`, пропуск `acceptance.md`). | 1. В `GEMINI.md` и `rules/AGENTS.md` плагина добавлено требование проверять `Showing lines X-Y of Z` и дочитывать обязательные файлы до `Z`.<br>2. Перехватчик `SessionStart` в проекте автоматически подгружает раздел «Жёсткие ограничения» и правила прогона тестов прямо в стартовый контекст. |
| **Потеря правил при вызове подчинённых агентов** (в поручениях не передавался `rules.md`, терялся номер блока). | В плагин вынесены три преднастроенных агента (`pd-test-author`, `pd-implementer`, `pd-reviewer`), у которых требования роли и чтение `rules.md` и `CLAUDE.md` зашиты в системную инструкцию. |
| **Подмена независимого ревью вторым шагом `/boost`** (`DeepCoderImprovementWorker` сам правит файлы, а координатор записывает это как ревью). | 1. У агента `pd-reviewer` в списке `tools` физически отсутствуют инструменты записи.<br>2. Введен регламент запуска `/boost` (см. раздел 2 ниже): для ревью разрешены только `pd-reviewer` или `DeepInvestigator` с проверкой пустого `git diff`. |
| **Подгонка боевого кода под дефектную заглушку** и улучшения сверх ТЗ после заморозки тестов. | 1. В системных правилах агента `pd-implementer` и в `GEMINI.md` прописан прямой запрет.<br>2. Перехватчик `PreToolUse` блокирует правку замороженных тестов при наличии файла снимка `.agents/state/frozen_tests.sha256`. |
| **Запуск опасных команд в режиме Turbo без песочницы** (чтение `.env`, живые флаги, коммит/пуш без спроса). | Перехватчик `PreToolUse` (`hooks.json`) жёстко блокирует (`deny`) чтение `.env` и принудительно спрашивает владельца (`force_ask`) перед `--acknowledge-live-orders`, `git commit`, `git push` в `main`/`release` и изменениями служб на сервере. |

## 2. Распределение ролей и моделей (только для Antigravity)

С учётом лимитов (`Gemini 3.8` — безлимитно, `Gemini 4` — большой лимит, `Claude Opus 5.5` и `Sonnet 5.5` — малый лимит):

| Роль / Этап процесса | Модель и уровень `effort` | Примечание |
| --- | --- | --- |
| **1. Изучение, ТЗ и архитектура** (шаги 1–3) | **Gemini 4** `high` / `xhigh` | Сбор фактов, подготовка ТЗ, разбор спорных случаев и план блоков. |
| **2. Координатор блоков** (поручения, сверка снимков, отчёты) | **Gemini 4** `medium` | Ведёт состояние задачи, вызывает агентов по образцу и сверяет чеклист приёмки. |
| **3. Автор тестов (вне денежного пути)** | **Gemini 3.8** `high` + `/boost` | Второй проход `/boost` помогает отловить зависания и случайные выходы в сеть. |
| **4. Автор реализации (вне денежного пути)** | **Gemini 3.8** `high` | Обычный запуск агента `pd-implementer` (без `/boost`, либо со строгим запретом правок сверх ТЗ). |
| **5. Тесты и реализация денежного пути / предохранителей** | **Gemini 4** `high` | Две отдельные сессии (`pd-test-author` и `pd-implementer`) на старшей модели Gemini. |
| **6. Первичное ревью блока** (отсев мелких дыр, дифф и поломки) | **Gemini 4** `high` | Только для чтения: агент `pd-reviewer` или `DeepInvestigator`. Ловит очевидные недочёты до траты лимита Claude. |
| **7. Чистовое ревью блока / приёмка** (поиск неочевидных дыр поломками) | **Opus 5.5** `xhigh` — для денежного пути и сложных блоков;<br>**Gemini 4** `high` — для простых блоков с финальным ревью всей задачи на **Opus 5.5** `xhigh` | Подключается после первичного ревью на `Gemini 4`, чтобы укладываться в один круг. |
| **8. Механические действия** (`check.sh`, `mutate.py`, выгрузки, сводки) | **Gemini 3.8** `medium` | Быстрые проверки без расхода лимитов старших моделей. |

## 3. Порядок использования `/boost` и образец поручения в Antigravity

### Образец поручения подчинённому агенту в Antigravity

Младшие модели Gemini при передаче задачи склонны терять вызов навыка, ссылку на `rules.md` и номер текущего блока. Поэтому координатор в Antigravity составляет поручение подчинённому агенту (`pd-test-author`, `pd-implementer`, `pd-reviewer` или `/boost`) строго по этому образцу без пропуска полей:

```text
Навык и правила:
- Задача выполняется по навыку product-development (исходный вызов: «…»).
- Первым делом прочитай целиком до последней строки:
  1) обязательные правила навыка: references/rules.md и references/handoffs.md;
  2) проектный файл правил (CLAUDE.md / AGENTS.md).

Роль и жёсткие ограничения:
- Твоя роль: [Автор тестов | Автор реализации | Независимый ревьюер].
- [Для автора тестов]: пиши только тесты по ТЗ и архитектуре; не создавай черновик рабочей реализации; проверяй боевое поведение через настоящую сборку и учитывай назначенные в ТЗ намеренные поломки.
- [Для автора реализации]: реализуй только принятые требования текущего блока; не изменяй файлы тестов, фикстуры и настройки проверок; не подгоняй боевой код под дефекты тестовых заглушек (при дефекте заглушки или теста остановись и верни описание координатору); ничего сверх ТЗ не добавляй — любые дополнения выноси вопросом владельцу.
- [Для независимого ревьюера]: режим только для чтения рабочей копии — не изменяй код, тесты или документы (итоговый git diff рабочей копии обязан остаться пустым); проверь критерии ТЗ собственными намеренными поломками во временной копии (или проектным инструментом мутаций) через настоящую сборку.

Проверенное состояние и границы блока:
- Текущий блок: № …, цель и границы: …
- Базовое состояние файлов (commit / рабочая копия): …
- Принятые версии: ТЗ (v…), архитектура и план (v…), снимок тестов (если есть): …
- Действующие исключения (если согласованы): …
- Файлы для чтения: … (что читать и трогать не нужно: …)
- Команды проверки и условие остановки: …
```

### Регламент `/boost`

Команда `/boost` запускает оркестратор со встроенными конвейерами `DeepCoder` (пишет и правит код в два прохода: `WorkerL0` → `ImprovementWorker`) и `DeepInvestigator` (исследует без правки файлов).

1. **Написание тестов (Шаг 4):** использовать `/boost` **можно**. Второй исполнитель находит зависания таймеров и выходы в настоящую сеть.
2. **Реализация (Шаг 5):** рекомендуется запускать агента `pd-implementer` без `/boost`. Если запускается `/boost`, в текст поручения обязательно включается ограничение:
   > «Второй исполнитель (`ImprovementWorker`) исправляет только прямое несоответствие критериям ТЗ. Любые улучшения сверх ТЗ, изменение тестовых файлов и подгонка боевого кода под тестовые заглушки запрещены; спорные места выносятся вопросом владельцу».
3. **Независимое ревью (Шаг 6):** запускать `DeepCoder` **запрещено** (его второй проход редактирует файлы и является доработкой автора, а не ревью). Для ревью используй только агента `pd-reviewer` или `DeepInvestigator` и проверяй, что `git diff` после сессии пуст.

## 4. Подключение плагина на каждом компьютере

Плагин `product-development-agy` хранится в этом репозитории в папке `plugins/product-development-agy/`. Подключите его символической ссылкой в глобальный каталог плагинов Antigravity:

```sh
PROCESS_REPO="$HOME/Projects/ai-development-process"
mkdir -p "$HOME/.gemini/config/plugins"
ln -s "$PROCESS_REPO/plugins/product-development-agy" "$HOME/.gemini/config/plugins/product-development-agy"
```

После создания ссылки перезапустите Antigravity, чтобы среда обнаружила плагин и его агентов (`pd-test-author`, `pd-implementer`, `pd-reviewer`).
